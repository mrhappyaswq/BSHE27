RTT is the browser request → complete response-body time, before JSON parsing or JPEG decoding. It includes server waiting and transport, not one-way radio latency or full FC-to-screen delay. Percent change = (image − telemetry) ÷ telemetry × 100; multiplier = image ÷ telemetry. Counts cover completed requests since Reset; means and percentiles use the latest 100 successful requests per mode. Request failures (including timeouts or invalid responses) are not raw radio packet-loss measurements. Heartbeat age starts when the ESP32 receives it, not when the FC generates it. Historical results may include different loads: reset before each controlled test. Telemetry continues while video/snapshots run; the camera still captures onboard when video downloads are off.

Board FPS measures completed sensor JPEG frames, not the sensor's theoretical maximum. Browser FPS counts distinct decoded frames, averaged over two seconds. Request time includes waiting for the next frame, transfer and JPEG decoding. Frame age is measured on the board before sending; it is not synchronized end-to-end latency. JPEG compression runs inside the camera sensor; 0 ms of ESP32 encoding does not mean zero sensor processing time. Image recognition is not installed. Multiple viewers share bandwidth.

Exposure and gain


Connect USB or read the settings over Wi-Fi.

Short exposure reduces motion blur but can darken the image. More gain brightens it and adds noise. Presets apply manual exposure with the gain shown above. Auto restores automatic exposure and gain; night-mode frame extension stays off. Values are calculated from sensor register readback, not an optical shutter measurement. Settings reset to Auto on reboot.

Connect a wired laptop

Use a data-capable cable in the board's native USB-C socket (the one connected to the ESP32-S3, often marked USB). The TTL/CH340 socket remains available for uploading and the console. Open the offline viewer in desktop Edge or Chrome, click Connect USB, and choose USB JTAG/serial debug unit / the Espressif device. Wi-Fi is not needed for USB viewing. This is a browser viewer, not a Windows webcam device.

Download offline USB viewer

If USB permission is unavailable on this Wi-Fi page, download the viewer and open that saved HTML file in Edge or Chrome. The USB interface supports video and camera exposure/gain only; it cannot start a flight mission. Video delivery pauses during missions.
